# App improvements: model factory, metric hardening, live-status caption, cost panel, deploy reliability

The change routes every live Bedrock model construction through a single `make_model` factory in `app/agent_utils.py`, hardens Module 2 metric-dict reads to `.get()`, adds an honest live-vs-local AWS status caption under each module page title, streams single-agent chat on Module 1 Parts 1/3, adds an estimated per-session cost panel to Module 4, and makes the deploy/infra scripts reliable (CFN-driven `.env` generator, Bash-3.2-safe Module 3 user loop, deterministic EC2 git reset, and a trimmed evaluator CFN stack). The app-side and deploy-side work is complete and matches the plan: the factory is the only live construction path, `temperature` is never passed, M5 economy keeps `apac.amazon.nova-micro-v1:0`, Home keeps its status line with no caption added, and the offline pytest suite passes (10 passed, 1 skipped).

Watch for: one unrelated, regressing file — `demos/infra-agentcore/config.env` — was swept into the diff. It drops `ToolSelectionEvaluatorId`/`ComplianceEvaluatorId` (which the running app reads) and introduces a malformed `export None=""` line (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The model-construction story is solid. `make_model(purpose, model_id=None, **overrides)` resolves the id by precedence (explicit arg > session_state > purpose default), validates against the allow-list with a silent fallback, always sets `region_name`, honors `max_tokens`, merges overrides last, and hard-pops `temperature` before constructing. Every live `BedrockModel(...)` call across the five pages and `agentcore_utils` now routes through it; the only `BedrockModel(` tokens left in page code are inside `st.code(...)` display strings (M5:381, M2:173/320/420), which are documentation, not live construction.

The UI additions are scoped correctly. `live_services_caption()` renders one guarded `st.caption` at module scope right after `inject_css()` on all five module pages and is absent from Home; no per-service sidebar badges were reintroduced. The Module 4 estimated-cost panel is a bordered container labeled "Estimated session cost" with a "not billing-accurate" caption, reads every metric via `.get()`, and leaves the thread-safe tool counter and per-turn metric columns untouched. Module 1 streaming wraps both the pills and chat_input paths for Parts 1 and 3 with `st.write_stream(chat_stream(...))` and still feeds the full streamed string to the judge.

The deploy/infra work checks out. `generate-env.sh` derives every value from `describe-stacks` at runtime (stack names and output keys are not resource ids), writes the two fixed table names as literals, and emits only resolved keys. The evaluator CFN stack dropped `OnlineEvaluationConfig` and its support resources/outputs while keeping both evaluators and their id/arn outputs. Module 3's deploy loop is `declare -A`-free with all five hero users intact and a `DEMO_USER_PASSWORD` override; `sync-ec2.sh` uses `git fetch && git reset --hard origin/main`.

The one gap is `demos/infra-agentcore/config.env`: it is not referenced by the plan or any FEAT file, yet it was modified in a way that removes evaluator ids the app resolves and adds a broken `export None=""` line. This is an unrelated change that regresses resource references and should be reverted.

### `make_model` as the single live construction path

`agent_utils.make_model` is the only place a `BedrockModel` is instantiated for runtime use (`agent_utils.py:103`, `return BedrockModel(**kwargs)`). The id resolution is explicit-arg > session_state (`cfg_MODEL_ID` for generation, `cfg_JUDGE_MODEL_ID` for judge) > purpose default, and the resolved id — including an explicit one — is validated against `_VALID_MODEL_IDS` before use, so a stale selection or a bogus explicit id falls back rather than crashing construction. `region_name` always comes from `AWS_REGION` or `ap-southeast-1`, `max_tokens` honors `cfg_max_tokens`, and `**overrides` merge last. `temperature` is removed via `kwargs.pop("temperature", None)` immediately before construction, so even a caller passing it cannot leak it to claude-haiku-5.x — verified directly by the `test_make_model_never_passes_temperature` monkeypatch test.

Call-site migration is complete. The judge sites (M1 x2, M2 context-failure, M3 x2, M4 Part 3 with `max_tokens=1024`, and the `agentcore_utils` evaluate fallback) use `make_model("judge", ...)`; generation sites preserve their overrides (`M2` prompt-caching `cache_tools="default"`, `M5` economy `model_id="apac.amazon.nova-micro-v1:0", max_tokens=1024`, `M5` premium `max_tokens=2048`). The four remaining `BedrockModel(` matches in page code sit inside `st.code(...)` blocks and are display-only.

### Module 2 metric reads

The bare `m['inputTokens']`-style reads the plan called out are gone — the targeted grep for `(m|prev|latest|metrics|entry)['...']` on the listed token keys returns nothing in `2_Module_2_Context.py`, and the `st.code` display block that prints `usage['cacheReadInputTokens']` was correctly left alone (it is a string, not a dict read).

### Module 4 estimated-cost panel

The panel is a `st.container(border=True)` titled "💰 Estimated session cost" with a `st.caption` stating "Estimated (not billing-accurate)" for the active model id. Token sums and cost all read through `.get(...)`, and `estimate_cost` draws from a per-1K price table keyed by the five valid ids with a default fallback for unknown ids. The thread-safe `m4p1_tool_counter` (plain list mutated from the worker thread) and the existing per-turn metric columns are untouched.
