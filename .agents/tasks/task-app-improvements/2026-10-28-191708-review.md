# Central model factory, honest live/local signalling, and deploy hardening for the ADAS demo app

This change routes every live Bedrock model construction in the Streamlit app through a single `make_model` factory, adds an honest "live AWS vs local simulation" caption to the five module pages, surfaces an estimated per-session cost panel on Module 4, streams the two single-agent chat parts of Module 1, and hardens the deploy/infra scripts (deterministic EC2 sync, Bash-3.2-safe Cognito seeding, env-var password override, a `.env` generator driven by CloudFormation outputs, and removal of the CFN resource that broke evaluator stack deploys). It also adds an offline-by-default pytest suite that locks in the regressions this session fixed. The motivation is consistency (one place that guarantees no `temperature` is ever sent to claude-haiku-5.x and that stale model selections fall back safely) and operational reliability (the evaluator stack now validates, the EC2 sync is idempotent, user seeding runs on the shipping macOS Bash).

Watch for: nothing blocking. The economy tier correctly keeps `apac.amazon.nova-micro-v1:0` (confirmed), the four remaining `BedrockModel(` references are all inside `st.code` display blocks (confirmed), and Module 1's judge still receives the full streamed string (confirmed).

**Verdict**: APPROVED

## High-level view

The factory `make_model(purpose, model_id, **overrides)` in `agent_utils.py` is now the only path that builds a `BedrockModel` at runtime. It resolves the id by precedence (explicit arg > session_state > purpose default), validates against the allow-list so a stale selection can't crash construction, always sets region from `AWS_REGION`, and unconditionally strips `temperature`. Every page and `agentcore_utils` judge site was migrated to it; the only surviving `BedrockModel(` tokens are teaching snippets inside `st.code`.

The live/local caption is a single guarded `st.caption` in `style.py` called once per module page and deliberately absent from Home. It degrades to silence on any failure rather than breaking the page, and it reads the existing `get_agentcore_status()` rather than re-adding per-service sidebar badges.

Module 4 gains a bordered "Estimated session cost" panel backed by `estimate_cost`, which carries an explicitly illustrative price table and is labeled not-billing-accurate at the point of display. All token reads in the panel use `.get(...)`.

Module 1 Parts 1 and 3 now stream via `st.write_stream(chat_stream(...))`, capturing the streamed text into `resp` so the judge and the message log keep working. Module 4 Part 1 was correctly left blocking because it depends on the metrics/tool-count return object.

On the deploy side: the evaluator CFN drops `OnlineEvaluationConfig` (and its now-orphaned log group and role) while keeping both evaluators and their id/arn outputs; `sync-ec2.sh` switched from `git pull` to `git fetch` + `reset --hard origin/main`; the Module 3 seeding loop replaced the Bash-4 associative array with a Bash-3.2 here-doc while preserving all five hero users and the permanent-password step; and `generate-env.sh` derives every value from CloudFormation at runtime with no hardcoded ids.

### `make_model` as the single construction path

`get_model()` is now a one-line delegate to `make_model("generation")`, and every judge/agent site that previously built `BedrockModel(...)` inline — the two Module 1 judges, the Module 2 context-failure judge, the two Module 3 judges, the Module 4 Part 3 judge (`max_tokens=1024` preserved), the Module 5 economy/premium tiers, the Module 2 prompt-caching agent (`cache_tools="default"` preserved), the Module 2 summarizing-manager agent, and the `AgentCoreEvaluator.evaluate` local fallback — now calls the factory with its original overrides intact (confirmed by reading the diff at each site).

The factory's safety properties are the reason this consolidation matters. The resolved id is checked against `_VALID_MODEL_IDS` and falls back to the purpose-specific default when invalid, so a stale `cfg_MODEL_ID` in session_state can't raise at construction (confirmed; the pytest suite exercises the `model_id='bogus'` path). `temperature` is popped from kwargs as the last step, which is a hard guarantee rather than a convention — this is the regression that motivated the refactor and it's now enforced in one place (confirmed at `agent_utils.py:101`).

The four `BedrockModel(` matches that remain in `pages/` are all inside `st.code("""...""")` teaching blocks (M2 lines 173/320/420, M5 line 381 — each verified by reading the surrounding lines). These are display strings the plan explicitly scopes out, so leaving them is correct.

### Live/local caption, and its deliberate asymmetry with Home

`live_services_caption()` renders one line listing which services `get_agentcore_status()` resolved (green) or a local-simulation line (white) with the region. It's wired into all five module pages immediately after `inject_css()` and is absent from Home (confirmed: five invocations, zero in `Home.py`). The whole body is wrapped so any exception renders nothing — a page-level caption should never be able to break the page, and this fails to silence rather than fails loud, which is the right call for a non-essential status line. No per-service sidebar badges were re-added.

### Estimated session cost on Module 4

The new bordered panel sums session tokens and latency from `m4p1_metrics` and shows `estimate_cost(model_id, input, output)`. The price table is documented in-code as illustrative and the panel caption repeats "Estimated (not billing-accurate)" at the point a reader sees the number, so the honesty label travels with the value rather than living only in a comment. Every metric read in the panel uses `.get(..., 0)`.

### Streaming Module 1 without breaking the judge

Parts 1 and 3 replaced the blocking `chat_response` + spinner with `resp = st.write_stream(chat_stream(...))`. The captured `resp` is what gets appended to the message log and passed to `judge_response`/`judge_orchestrator_response` (confirmed: the judge calls at lines 147/162/315/332 receive `resp`, the streamed string). Module 4 Part 1 was correctly left on `chat_response_with_metrics` because it needs the metrics/tool-count object that streaming would discard — this asymmetry is intentional and matches the plan.

### Deploy and infra hardening

The evaluator CFN removes `OnlineEvalConfig` plus the `EvaluationLogGroup` and `EvaluationExecutionRole` that only existed to support it, and drops the two online-eval outputs, while keeping `ToolSelectionEvaluator`/`ComplianceEvaluator` and their id/arn exports (confirmed: zero `OnlineEval*` references remain, both evaluators and their id outputs present). That removes the resource that failed early CFN validation.

`sync-ec2.sh` now runs `git fetch origin main && git reset --hard origin/main` as the ubuntu user, making the EC2 update deterministic instead of subject to merge/divergence failures from `git pull` (confirmed: zero `git pull origin main`, one `reset --hard origin/main`). The `.env` copy and service restart are preserved.

The Module 3 seeding loop replaced `declare -A USERS` (Bash-4-only, broken on the shipping macOS Bash 3.2) with a here-doc of `email,role,dept,hero,max_refund` rows read by `while IFS=',' read`. All five hero users and the permanent-password step survive, and `DEFAULT_PASSWORD` became `"${DEMO_USER_PASSWORD:-Hero\$ecure1!}"` so the default is unchanged but overridable without editing the script (confirmed: `bash -n` passes, zero `declare -A`, override documented in `deploy/README.md`).

`generate-env.sh` queries the same seven stacks the app reads and emits a key only when its value resolves, deriving everything from CloudFormation at runtime — no hardcoded resource ids (confirmed: `bash -n` passes, the two DynamoDB table-name constants are the only literal values and they match the app defaults `m3-demo-customers`/`m3-demo-orders`).
